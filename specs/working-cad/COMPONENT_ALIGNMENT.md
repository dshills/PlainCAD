# Align component geometry

Open **Move component**, then expand **Align to another component**. Choose planar faces, straight edges or endpoints. Pick a source on the active component and a matching target on another component using the named lists or highlighted preview markers. Orbit or Fit to reveal markers; named choices remain available if markers overlap or lie outside the view.

Choose **Align selected geometry** to prepare a rigid pose. Faces align their normal directions and plane separation while preserving tangential translation; they do not center finite faces. **Oppose face normals** defaults on. Signed face clearance is in millimeters along the target normal; negative values place the source plane on the opposite side. Straight edges align direction and midpoint, with an optional direction reversal; endpoints coincide without rotating. These operations snap exact native references, not sampled mesh chords. The shortest directional rotation is used, with a deterministic axis for opposite directions. Rotation still uses the authored component origin.

The live placement is temporary. Apply requires the current successful native preview for that exact pose and adds one Undo step. Changing choices or clearance requires another Align; typing must finish with Enter or blur. Cancel and stale project/component/rebuild/session changes cannot publish a placement. Face marker centroids come from bounded native tessellation for display only; exact plane origins/normals govern alignment. Marker preparation permits at most 250,000 triangle visits across all faces; faces beyond this budget keep their named list choices and have no marker, rather than using a partial centroid.

Supported picks are retained native authored distance-extrusion cap endpoints and straight cap edges, and validated cap/straight-side face planes. Curved edges, arbitrary boolean topology and mixed point/edge/face pairs are unavailable. Face markers represent a plane role: the centroid of coplanar triangles may lie in an opening or between separate regions; use its named choice to disambiguate. Add another component with compatible native geometry before using alignment. Alignment stores a static component placement, with no persistent mate, joint, motion constraint or collision avoidance.

Native browser acceptance verifies actual pointer selection, face clearance, edge rotation, endpoint cancellation, unchanged native volume/solid count, Undo/Redo, parameter edits, save/open and placed positive-winding STL. Unit and component tests cover degenerate directions, opposite normals, gimbal rotations, finite limits, pending choices and invalid clearance.
